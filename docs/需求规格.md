# SA · 股析 — 需求规格说明书

| 项目 | 内容 |
|---|---|
| 软件名称 | SA（股析，Stock Analysis） |
| 文档版本 | v0.1（原型阶段确认版） |
| 对应原型 | `design/web/`（23 页）、`design/app/`（19 页） |
| 适用范围 | 个人自用为主，可扩展至小团队共用 |

---

## 1. 项目概述

### 1.1 目标

输入一个股票名称或代码，聚合公开披露资料，自动形成一张**分析矩阵**，把一家公司拆成 8 个可快速扫读的维度，
并用表格与图形化方式呈现，服务于**趋势投资**场景下的「一眼得到有用信息」。

### 1.2 交付形态

| 端 | 形态 | 技术 |
|---|---|---|
| 服务端 | HTTP 服务（REST + 实时推送） | ASP.NET Core Web API（.NET 10） |
| Web 前端 | 响应式单页应用 | React 19 + Vite + TypeScript + Tailwind + shadcn/ui + ECharts |
| 移动端 | **响应式 Web + PWA**（不做独立 App，不使用 Avalonia / MAUI） | 同上，外加 Service Worker / Web Push |
| 数据库 | 元数据 + 时序文件 | SQLite（元数据）+ DuckDB/Parquet（时序） |

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 分析矩阵 | 个股页 8 个分析模块的统称，可卡片堆叠总览，也可切单模块专注模式 |
| 拓扑图 | 表达「谁影响谁」的四种图：事件因果网络、公司股权关系、产业链传导、自上而下影响传导 |
| 功能点（function point） | 权限的最小授权单位，如 `stock.capital`、`export.data` |
| 数据口径 | 某指标的来源、计算方式与更新时间，界面通过问号提示展示 |
| 自选股 | 用户关注的股票集合，唯一享有盘中实时推送的数据范围 |

## 2. 用户与角色

| 角色 | 定位 | 权限概要 |
|---|---|---|
| 管理员 | 系统所有者 | 全部功能点 + 后台管理（用户 / 权限 / 数据源 / 安全） |
| 普通用户 | 小团队成员 | 8 个模块只读 + 自选 + 选股 + 提醒；无导出、无后台 |
| 访客 | 只读演示 | 仅市场概览 + 趋势 + 搜索，数据范围仅自选股 |

- 账号由管理员手工创建，**不开放注册**。
- 角色与功能点为多对多关系，支持自定义角色（复制现有角色后微调）。

## 3. 市场与数据范围

| 项目 | 结论 |
|---|---|
| 市场范围 | A 股全市场：沪深主板 + 创业板 + 科创板 + 北交所 |
| 标的类型 | 股票；指数用于市场概览；ETF / 可转债 / 港股 / 美股 **不在本期范围** |
| 交易日历 | 沪深交易所交易日历，用于调度盘中/盘后任务 |
| 涨跌停规则 | 按板块区分（主板 ±10%、创业板/科创板 ±20%、北交所 ±30%、ST ±5%） |
| 货币单位 | 人民币；金额统一「亿元」，成交量「万手」/「亿股」 |

## 4. 功能需求

### 4.1 全局搜索（FR-SEARCH）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-SEARCH-01 | 支持代码精确匹配 | 6 位代码，如 `300750` |
| FR-SEARCH-02 | 支持名称模糊匹配 | 如 `宁德` → 宁德时代 |
| FR-SEARCH-03 | 支持拼音首字母匹配 | 如 `ndsd` → 宁德时代 |
| FR-SEARCH-04 | 支持行业/概念关键词 | 如 `电池` → 该行业全部个股 |
| FR-SEARCH-05 | 顶栏常驻搜索框 | <kbd>⌘/Ctrl</kbd>+<kbd>K</kbd> 或 <kbd>/</kbd> 唤起，实时下拉 |
| FR-SEARCH-06 | 结果列表 | 代码、名称、板块、行业、现价、涨跌幅、换手、量比、PE、PB、市值、30 日迷你走势 |
| FR-SEARCH-07 | 二次筛选与批量操作 | 按板块 / 行业 / 市值筛选，支持勾选后批量加入自选 |
| FR-SEARCH-08 | 权限裁剪 | 数据范围受限的角色只返回授权范围内的结果 |

### 4.2 市场概览（FR-MARKET）

| 编号 | 需求 |
|---|---|
| FR-MARKET-01 | 主要指数卡片：上证 / 深证 / 创业板 / 科创50 / 北证50，含涨跌与成交额、迷你分时 |
| FR-MARKET-02 | 涨跌家数：上涨 / 下跌 / 平盘 / 涨停 / 跌停 / 涨跌比 |
| FR-MARKET-03 | 两市成交额与融资融券余额 |
| FR-MARKET-04 | 北向资金：近 5 个交易日净流入与累计 |
| FR-MARKET-05 | 行业热力（面积=涨跌强度，颜色=涨跌方向）与行业涨跌排行 |
| FR-MARKET-06 | 今日事件热点列表，含影响方向与相关股票链接 |
| FR-MARKET-07 | 成交额榜 / 涨幅榜 / 跌幅榜（剔除新股与 ST） |

### 4.3 分析矩阵（8 个模块）

个股页 `stock.html` 为矩阵总览：8 张摘要卡纵向堆叠，每卡含 3–6 个关键指标 + 缩略图，
支持折叠与**拖拽排序**（顺序存本机），右上标签可切换单模块专注模式。

#### 4.3.1 趋势与价格结构（FR-TREND）

| 编号 | 需求 |
|---|---|
| FR-TREND-01 | 日 / 周 / 月 K 线，前复权 / 后复权 / 不复权切换 |
| FR-TREND-02 | 均线 MA5/10/20/60（周期可在设置中改，最多 6 条） |
| FR-TREND-03 | 副图指标：成交量、MACD(12,26,9)、KDJ(9,3,3) 可切换 |

| FR-TREND-05 | 相对沪深 300 强弱曲线（20 / 60 / 120 日） |
| FR-TREND-06 | 价格结构定位：近 3 年分位、距 52 周高低点、站上 MA20 / MA250 幅度 |

| FR-EVT-04 | 时间轴泳道：按主体（政策 / 公司公告 / 行业 / 资金 / 机构）分泳道，圆点颜色=影响方向 |

## 6. 数据需求

### 6.1 数据源清单

| 数据源 | 覆盖数据域 | 频率 |
|---|---|---|
| 东方财富（公开接口） | 实时行情、财务报表、资金流向、龙虎榜、股东数据、机构评级 | 3s / 15:20 / 18:00 / 19:30 / 20:00 |
| 新浪财经（公开接口） | 实时行情、分时数据、指数行情 | 3s |
| 腾讯财经（公开接口） | 实时行情、公告标题、板块数据 | 3s（备用源） |
| 交易所公开数据 | 公告、龙虎榜、融资融券 | 19:00 |
| 巨潮资讯 | 公告全文、定期报告 | 07:30 / 12:30 / 19:30 |
| 国家统计局 / 央行 | 宏观指标、利率数据 | 事件驱动 |

- **采集层为纯 C# 直连公开 HTTP 接口，不引入 Python / AKShare 依赖。**
- 放弃券商研报与营业部观点原文抓取（反爬与合规风险高），改为汇总公开机构评级与盈利预测。

### 6.2 数据口径要求

- 每个指标必须在界面提供「数据口径」说明（来源 / 计算方式 / 更新时间），通过问号提示呈现。
- 需明确标注为**估算值**的口径：北向资金净流入、产业链成本占比与供货占比、筹码分布、关联方风险敞口。
- 2026E 及以后的财务数据为机构一致预期，不得与已披露数据混淆展示。

### 6.3 数据质量

- 采集失败自动重试（退避策略），连续失败降级到备用数据源。
- 数据源字段结构变更需记录告警并可快速适配。
- 财务数据以合并报表为准；单季度数据由累计值差分还原，需提示四舍五入差异。

## 8. 界面需求

### 8.1 页面清单

- 桌面端 23 页、移动端 19 页，清单与截图位置见 `design/README.md`。
- 个股页两种形态并存：**卡片堆叠总览**（一屏纵览）与**标签切换专注模式**（单模块深入）。

### 8.2 视觉与交互

| 项目 | 要求 |
|---|---|
| 风格 | **大气简约**：深色为主（中性近黑底 + 面板一档差分层），可切换浅色；**无装饰性渐变与光晕，卡片无描边**（16px 圆角，浅色主题仅极淡投影）；专业金融终端观感 |
| 涨跌色 | 默认红涨绿跌，可切为绿涨红跌；影响全部图表、表格与数字 |
| 数字 | 等宽字体 + `tabular-nums`，右对齐，保证小数点竖直对齐；**关键数字（行情价 / 目标价 / 命中数）放大（28–42px）作为视觉锚点** |
| 实时反馈 | 数字变动闪烁高亮；加载使用骨架屏；空态给出下一步建议 |
| 图表 | 全部使用 ECharts（K 线 / 桑基 / 关系图 / 热力 / 雷达 / 筹码 / 泳道 / 树图等 16 种）；图例与坐标轴低饱和、弱化网格 |
| 浮层 | 统一玻璃拟态（模糊 + 半透明 + 三级阴影）；**模糊仅用于浮层，页面内容不用** |
| 数据口径 | Web 端弱化的「?」问号常驻、hover 恢复并显示口径；说明文字一律灰字，不使用虚线框 / 色块容器 |
| 响应式 | 桌面 ≥1440 三栏；平板 1024–1439 导航收窄；手机 ≤767 单列 + 底部 Tab |
| 一致性 | 移动端复用同一套令牌与组件，差异仅在布局与手势 |

### 8.3 移动端特有要求

| 项目 | 要求 |
|---|---|
| 导航 | 底部 5 个 Tab（市场 / 自选 / 选股 / 通知 / 我的），详情页保留返回 |
| 触摸热区 | 所有可点击元素 ≥ 44×44 |
| 表格 | 精简列 + 横向滚动 + 首列冻结 |
| 手势 | 左滑删除、长按拖拽排序、下拉刷新、双指缩放（K 线 / 拓扑 / 矩阵） |

| 内容密度 | **一屏一主角，每页板块 ≤ 5 个**，超出移至 Web 端或折叠展开；正文基准 14px |
| 数据口径 | 每页底部统一一条灰字说明，不逐卡片标注 |
| 后台管理 | 仅 Web 端提供 |
