## 1. 解决方案结构

```
SA.sln
├── src/
│   ├── SA.Api/                 Web API 宿主（REST + SignalR + 静态前端托管）
│   ├── SA.Collector/           采集后台服务（HostedService + 适配器）
│   ├── SA.Application/         用例编排（查询 / 命令）
│   ├── SA.Domain/              领域模型与不变量
│   ├── SA.Infrastructure/      持久化、缓存、推送、通知、授权实现
│   └── SA.Contracts/           请求 / 响应 DTO（前后端共享契约）
├── tests/
│   ├── SA.Domain.Tests/        领域逻辑与指标计算
│   ├── SA.Application.Tests/   用例
│   └── SA.Api.Tests/           接口与授权
├── web/                        React 前端（独立构建，产物由 SA.Api 托管）
└── design/                     原型（本仓库已包含）
```

**依赖方向**：`Api → Application → Domain`，`Infrastructure` 实现 `Application`/`Domain` 定义的接口，禁止反向依赖。

## 3. 关键流程

### 3.1 打开个股分析（一次请求聚合）

```
用户输入代码
   │
   ▼
GET /api/stocks/{code}/overview
   │
   ├─ 命中缓存？ ──是──▶ 直接返回
   │        │否
   │        ▼
   │   并行取：行情快照 / 财务 / 股权 / 资金 / 行业 / 事件 / 风险 / 评级
   │        │
   │        ▼
   │   组装 8 个模块的摘要指标 + 缩略图数据 + 结论摘要
   │        │
   └────────┴──▶ 写缓存（5 分钟）并返回
```

- 摘要卡与专注页共用同一数据源，专注页请求更细的序列数据。
- 图表序列（K 线最多 240 根）一次性返回，避免多次往返。

### 3.2 采集流程

```
交易日历调度 ──▶ 适配器拉取 ──▶ 规范化（单位 / 口径对齐）
   │                                  │
   │                                  ▼
   │                          写入 Parquet / SQLite
   │                                  │
   │                                  ▼
   └──▶ 失败：退避重试 → 仍失败则降级到备用源 → 记录失败明细与告警
```

| 任务 | 周期 | 数据源 |
|---|---|---|
| 全市场行情快照 | 交易时段每 3s | 东方财富 + 新浪 |
| 自选股实时推送 | 交易时段每 3s | 新浪 |
| 日线行情入库 | 每交易日 15:30 | 东方财富 |
| 资金流向采集 | 每交易日 15:20 | 东方财富 |
| 财务报表同步 | 每交易日 18:00 | 东方财富 |
| 龙虎榜与两融 | 每交易日 19:00 | 交易所公开数据 |
| 公告抓取与事件抽取 | 07:30 / 12:30 / 19:30 | 巨潮资讯 + 交易所 |
| 机构评级汇总 | 每交易日 20:00 | 东方财富 |
| 舆情情绪计算 | 每交易日 20:30 | 新闻资讯 |
| 技术指标计算 | 每交易日 16:00 | 本地计算 |
| 提醒规则巡检 | 交易时段每 30s | 本地计算 |
| 数据源连通性探测 | 每 5 分钟 | 全部数据源 |

### 3.3 条件选股流程

```
条件集合 ──▶ 校验 ──▶ 按索引筛选全市场快照 ──▶ 排序 ──▶ 分页返回
                          │
                          └─ 记录各条件逐步收敛的命中数与耗时（供界面展示）
```

- 基于每日批量更新后的快照，盘中结果不随行情变化（与界面提示一致）。
- 结果缓存 5 分钟；保存的策略仅存条件 DSL，不存结果。

### 3.4 提醒触发流程

```
行情/指标/资金/事件更新 ──▶ 规则巡检（30s） ──▶ 命中判定
                                                   │
                        ┌──────────────────────────┴───────────────────────┐
                        ▼                        ▼                        ▼
                  写触发历史              站内通知（落库）         Web Push + 震动标记
                        │                        │                        │
                        └──────────── 合并策略：同规则 5 分钟一次 ────────┘
                                       免打扰：仅站内，不推送
```

### 3.5 权限裁剪流程

```
登录 ──▶ 解析角色 ──▶ 取角色功能点集合 ──▶ 下发前端
                              │
                              ├─ 前端：过滤路由与菜单（不注册无权限路由）
                              └─ 后端：每个接口用功能点策略校验，403 统一处理
```

## 6. 关键技术方案

### 6.1 指标计算

- MA / EMA / MACD(12,26,9) / KDJ(9,3,3) / BOLL(20,2) / RSI(6,12,24) 由后端批量计算并落 Parquet，前端只负责渲染。
- 相对强弱 = 个股累计收益 − 沪深 300 累计收益（同区间）。
- 价格分位 = 当前价在近 3 年（或近 250 日）收盘价分布中的百分位。

### 6.2 单季度财务数据

由累计值差分还原：`Q(n) = 累计(n) − 累计(n−1)`；Q1 直接取累计值。界面提示可能存在的四舍五入差异。

### 6.3 筹码分布（估算）

按换手率衰减模型由历史成交估算：

```
对每根历史 K 线：将当日成交量按当日价格区间分配为筹码；
随后每日按换手率 t 对全部价格档位做衰减：chips[p] *= (1 − t)
输出：价格 → 筹码占比、平均成本（加权）、获利盘比例（现价下方占比）、
      集中度 = (P90 − P10) / (P90 + P10)
```

明确标注为估算值，仅作相对参考。

### 6.4 事件抽取与因果链

| 步骤 | 方法 |
|---|---|
| 抓取 | 公告标题与新闻正文，落原始归档 |
| 抽取 | 规则引擎：关键词 + 模板（业绩/订单/政策/监管/减持…）+ 来源映射 |
| 类型判定 | 命中模板即赋 EventType |
| 影响方向与强度 | **人工标注**（0–100，负值表示压制） |
| 因果连线 | 人工标注源 → 目标 + 强度 + 说明 |
| 泳道 | 按主体分组，按日期排序 |
| 自上而下 | 宏观点 ← 政策文件与宏观数据；传导强度由人工打分（依据历史弹性） |

### 6.5 资金面口径

- 分层：按逐笔成交金额分层（超大单 ≥ 200 万元，大单 20–100 万股，中单 4–20 万股，小单 < 4 万股）。
- 主力净流入 = 超大单 + 大单净额（口径可在设置中切换）。
- 背离检测：近 N 日资金累计净流入方向与价格涨跌方向相反即标记。

### 6.6 权限判定

- 后端：`IAuthorizationHandler` 按功能点编码判定，接口特性标注所需功能点。
- 前端：登录后取功能点集合，过滤路由表与菜单；按钮级（如导出、编辑标注）按功能点隐藏。
- 数据范围：`data.scope.watchlist` 的角色，查询接口自动追加自选股过滤条件。
