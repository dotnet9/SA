## 1. 架构目标与约束

### 1.1 目标

1. **单机可跑**：一台服务器（或 NAS）即可承载全部能力，运维成本接近零。
2. **数据可换**：采集层适配器可插拔，公开接口改版时只改适配器，不动业务与界面。
3. **界面即原型**：前端严格按 `design/` 的设计令牌与页面结构实现，原型即视觉验收基准。
4. **权限可配**：功能点集中枚举，角色可自定义，后端与前端共用同一份权限判定。
5. **实时有边界**：只对自选股做秒级推送，控制内存与带宽开销。

### 1.2 关键决策与理由

| 决策 | 结论 | 理由 |
|---|---|---|
| 前端框架 | React 19 + Vite + TS，**放弃 Blazor** | 图表生态（ECharts / shadcn/ui）成熟；静态产物可由 .NET 托管，也可独立部署；原型即 React 的样式来源 |
| 移动端 | **响应式 Web + PWA**，不做 Avalonia / MAUI 独立 App | 一套代码覆盖三端；PWA 提供通知栏提醒与震动；独立 App 的维护成本与商店流程对自用场景不划算 |
| 采集层 | **纯 C# 直连公开 HTTP 接口**，不引入 Python / AKShare | 部署只依赖 .NET 运行时；无跨进程调用与 Python 环境维护；适配器模式应对接口变更 |
| 存储 | **SQLite（元数据）+ DuckDB/Parquet（时序）** | SQLite 零运维、单文件备份；时序数据列式存储压缩率高、扫描快；EF Core 做可切换抽象，日后可换 PostgreSQL |
| 实时通道 | SignalR（WebSocket，回退长轮询） | 与 ASP.NET Core 同栈；自选股订阅模型简单；无需引入消息队列 |
| 鉴权 | JWT + 刷新令牌（HttpOnly Cookie）+ TOTP | 无状态、易做多设备会话管理；2FA 抵御暴力破解 |
| 部署 | 反向代理 + HTTPS 域名，外网走 VPN 或隧道 | PWA 通知与 Service Worker 需要安全上下文；不直接暴露端口降低攻击面 |

### 1.3 约束

- 数据仅来自公开渠道，不做数据再分发，界面必须标注「不构成投资建议」。
- 公开接口存在频率限制与字段变更，采集必须可退避、可降级、可观测。
- 个人自用部署环境为 Windows / Linux 服务器或 NAS，内存预算 ≤ 4GB 可用。

### 3.1 容器职责

| 容器 | 职责 | 关键约束 |
|---|---|---|
| 反向代理 | TLS 终止、域名与路径路由、限流、静态资源缓存 | 手机外网必须 HTTPS |
| SA.Api | REST 接口、SignalR 推送、鉴权授权、静态前端托管 | 无状态，可水平扩展（预留） |
| SA.Collector | 定时采集公开数据、清洗、写库、上报监控指标 | 与 Api 同进程或独立进程（可拆） |
| 分析引擎 | 技术指标、财务增速、资金分层、筹码估算、拓扑数据生成 | 纯计算，无外网依赖 |
| 提醒调度器 | 规则巡检、命中判定、多渠道推送 | 盘中 30s 巡检 |
| 数据访问层 | SQLite 与 Parquet/DuckDB 的统一读写 | 读多写少，重查询走缓存 |
| 内存缓存 | 全市场快照、自选股订阅表、热门查询结果 | 快照约 5,400 条，内存占用可控 |

### 3.2 部署形态

- **本机 / 局域网**：`http://localhost` 或内网 IP 直接访问，用于开发与日常使用。
- **外网访问**：域名 + HTTPS（Let's Encrypt）或 VPN/隧道（Tailscale / WireGuard），不直接暴露端口。
- 前端产物由 SA.Api 托管，单进程部署；如需分离可放至任意静态托管。

### 4.2 SA.Collector 分层

```
SA.Collector
├── Scheduling/       交易日历 + 定时任务注册（行情 3s、盘后各时点）
├── Adapters/         每个数据源一个适配器实现
│   ├── IQuoteSource          实时行情与指数
│   ├── IFinancialSource      财务报表
│   ├── ICapitalFlowSource    资金流 / 两融 / 龙虎榜
│   ├── IAnnouncementSource   公告抓取
│   ├── IRatingSource         机构评级与一致预期
│   └── IMacroSource          宏观数据
├── Normalization/    原始字段 → 统一领域模型（含单位、口径对齐）
├── Resilience/       退避重试、熔断、降级到备用源、频率限制
└── Monitoring/       采集结果上报（成功时间 / 延迟 / 失败 / 行数）
```

**适配器可插拔**：新增数据源只需实现接口并注册，不改动业务与界面。

### 4.3 分析引擎组件

| 组件 | 职责 | 输出 |
|---|---|---|
| 技术指标计算器 | MA / EMA / MACD / KDJ / BOLL / RSI / 相对强弱 | 指标序列（落 Parquet） |
| 财务分析器 | 增速（同比 / 环比）、比率、单季度差分还原、财务评分 | 指标与增速表 |
| 资金分析器 | 分层聚合、主力净流入、背离检测、资金面评分 | 序列与评分 |
| 筹码估算器 | 按换手率衰减模型由历史成交估算筹码分布 | 价格→占比、平均成本、获利盘、集中度 |
| 事件抽取器 | 规则引擎（关键词 + 模板）从公告与新闻标题抽取事件 | 事件候选 + 类型 + 来源 |
| 传导图生成器 | 由人工标注的关系与推算的占比生成四种拓扑图数据 | 节点 / 边 / 强度 |
| 提醒判定器 | 按四类规则巡检并产生触发记录 | 触发事件 → 推送 |

**影响方向与强度（0–100，负值表示压制）由人工标注**；规则引擎只生成候选与类型，保证可信度。

## 5. 技术选型

| 层 | 选型 | 版本基线 | 说明 |
|---|---|---|---|
| 服务端 | ASP.NET Core Web API | .NET 10（本机 SDK 10.0.401） | 与现有 .NET 工具链一致 |
| ORM | EF Core | 随 .NET 10 | 做可切换抽象，便于日后换 PostgreSQL |
| 元数据库 | SQLite | 3.x | 单文件、零运维、易备份 |
| 时序存储 | DuckDB + Parquet | 最新稳定版 | 列式压缩、扫描快、可直接 SQL |
| 实时 | SignalR | 随 ASP.NET Core | WebSocket，自带回退 |
| 前端 | React + Vite + TypeScript | Node 25.2.1 / npm 11.6.2 | 静态产物、构建快 |
| 样式 | Tailwind + shadcn/ui | Tailwind 4.3.3 | 与原型 `tailwind.css` 同源 |
| 图表 | Apache ECharts | **6.1.0**（原型已内置该版本） | K 线 / 桑基 / 关系图 / 热力 / 雷达 / 筹码 / 泳道 |
| 移动端 | PWA（Service Worker + Web Push） | — | 通知栏提醒、震动、离线壳；不做独立 App |
| 认证 | JWT + 刷新令牌 + TOTP | — | HttpOnly Cookie 承载刷新令牌 |

## 6. 数据架构

### 6.1 存储分层

| 层 | 存储 | 内容 |
|---|---|---|
| 元数据 | SQLite | 用户、角色、功能点、角色功能点、自选股、分组、提醒规则、触发历史、通知、策略、日志、采集监控 |
| 时序 | Parquet（按标的 + 数据类型分文件） | 日线 / 周线 / 月线、资金流、两融、财务（报告期）、技术指标 |
| 缓存 | 内存 | 全市场快照、自选股订阅表、热门查询结果（TTL 数分钟） |
| 原始快照 | Parquet（可选归档） | 采集原文，便于口径追溯与重算 |

### 6.2 目录约定（示意）

```
data/
├── sa.db                       SQLite 元数据
├── parquet/
│   ├── daily/{market}/{code}.parquet        日线
│   ├── capitalflow/{year}/{code}.parquet    资金流
│   ├── finance/{year}/{code}.parquet        财务
│   ├── indicator/{year}/{code}.parquet      技术指标
│   └── archive/{source}/{date}/             原始归档
└── backups/                    定时备份
```

### 6.3 缓存与刷新策略

| 数据 | 缓存位置 | 失效方式 |
|---|---|---|
| 全市场快照 | 内存 | 盘中每 3s 覆盖，收盘后停止 |
| 自选股行情 | 内存 + SignalR 广播 | 3s 推送 |
| 个股分析结果 | 内存（TTL 5 分钟） | 对应数据域更新时主动失效 |
| 选股结果 | 内存（TTL 5 分钟） | 快照更新或条件变化 |
| 静态参照（行业、板块、股票列表） | 内存 + 进程启动加载 | 每日首次采集后刷新 |

## 7. 实时推送架构

```
采集器（3s）──▶ 内存快照 ──▶ 订阅管理器 ──▶ SignalR Hub ──▶ 各端
                                  │
                                  └─▶ 提醒调度器（30s 巡检）──▶ 命中
                                                              │
                            ┌─────────────────────────────────┴────────┐
                            ▼                     ▼                    ▼
                       站内通知            浏览器通知栏            震动标记
                       （落库）            （Web Push）        （移动端下发）
```

- 订阅模型：客户端连接时声明关注的自选股代码集合，服务端只推送这些标的。
- 降级：WebSocket 不可用时回退长轮询；页面失焦时前端降低渲染频率。
- 合并：同一规则 5 分钟内只提醒一次；免打扰时段仅写站内通知。

## 8. 部署架构

```
Internet ──▶ 域名 HTTPS ──▶ 反向代理 ──▶ SA.Api (:5000)
                                          │
                                    SA.Collector（同进程 HostedService）
                                          │
                            SQLite（sa.db） + Parquet 目录（本地磁盘）

```

| 项目 | 方案 |
|---|---|
| 进程管理 | Windows 服务 / systemd / Docker 容器 |
| TLS | Let's Encrypt 自动续期，或隧道服务托管证书 |
| 备份 | 每日收盘后复制 `sa.db` + 增量 Parquet，保留 30 天 |
| 日志 | 结构化日志落文件，按天滚动，保留 7 天 |
| 健康检查 | `/health`（存活）与 `/health/ready`（依赖就绪） |
| 时区 | 服务器统一 `Asia/Shanghai`，避免交易日调度错位 |

## 9. 安全设计

| 面向 | 措施 |
|---|---|
| 传输 | 全站 HTTPS；HTTP 仅用于 `localhost` 调试 |
| 认证 | JWT（短期）+ 刷新令牌（HttpOnly / Secure / SameSite Cookie）；登录失败 5 次锁定 15 分钟 |
| 二次验证 | TOTP，全部账号强制；异地登录（非同 /24 网段）额外验证 |
| 密码 | 最小长度 10、四类字符、不与最近 5 次重复、有效期 90 天；PBKDF2 / Argon2id 加盐哈希 |
| 会话 | 有效期 72 小时；单账号最多 5 个并发会话；支持逐条或全部强制下线 |
| 授权 | 功能点策略式授权（后端逐接口校验），前端按同一配置裁剪路由与菜单 |
| 限流 | 反代层按 IP 限流；应用层按账号配额（单日查询上限） |
| 防爆破 | 同 IP 1 小时失败 20 次封禁 24 小时；异常来源可加黑名单 |
| 数据外流 | 导出权限独立受控；导出记录写入日志 |

## 11. 关键技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 公开接口非官方、随时变更或封禁 | 数据断流 | 适配器隔离 + 多源降级 + 结构变更告警 + 原始数据归档可重算 |
| 频率限制（如 HTTP 429） | 采集失败 | 指数退避、请求合并、盘中仅轮询自选股 + 指数 |
| 北向资金口径变化 | 指标失真 | 明确标注为估算值，提供口径说明 |
| 筹码分布为模型估算 | 与真实持仓有偏差 | 标注为估算，仅作相对参考 |
| 事件抽取准确率有限 | 误判影响方向 | 规则引擎只生成候选，方向与强度由人工标注 |
| 全市场快照内存占用 | 内存压力 | 只保留必要字段的紧凑结构；如需扩展可改增量推送 |
| 权限绕过（前端隐藏但接口可调） | 越权 | 后端逐接口策略校验，前端裁剪仅用于体验 |
| 单机故障 | 服务中断 | 每日自动备份；SQLite 单文件可直接迁移到新机恢复 |

## 12. 演进路线

| 阶段 | 内容 |
|---|---|
| 一期 | 采集层（行情 + 财务 + 资金流 + 公告）→ 分析引擎 8 模块 → Web 端全功能 → 权限与后台 |
| 二期 | PWA 通知与震动、事件因果链人工标注界面、条件选股回测提示、多数据源降级完善 |
| 三期 | 行业景气度与宏观传导自动化、策略共享、增量推送优化、可选 PostgreSQL 切换 |
| 长期 | ETF / 可转债支持、移动端小组件（如需则另行包壳）、多租户 |
